# Independent Muse review

Reviewed October 17, 2026 with Muse Code, explicitly selecting `muse-wonder-full-1.0` at `xhigh`. The installed model-profile command confirmed that selection; a completed headless run returned a substantive critique. The review used a sanitized draft and requested design feedback without tools or external changes. It is a model review, not primary-source verification or a live interoperability test.

## Incorporated

- Optional repositories, generic resources, and a personal-assistant example.
- Separate read/receive/wake/continue/reply/act capabilities with evidence.
- Explicit per-channel listening choices and private/shared context boundaries.
- Existing-session continuity, desktop availability, finite work/reply budgets, task expiry, cancellation, and ambiguous-effect reconciliation.
- Capability-specific acceptance, user-facing addressing/status instructions, and generic handoff records.
- Separation of reusable core guidance from changing vendor-specific routes.

## Adapted or declined

- The suggestion to forbid personal assistants in an employer workspace was too broad. Membership, owner authorization, data audience, and organizational policy determine the permitted route.
- The proposed universal human approval for every external action would ignore existing user authorization. The package preserves actual authorized scope and real product/tool gates.
- A universal mention-only default would defeat requested conversation-following. The package makes delivery preferences explicit and defaults unresolved setups to assigned work.
- Muse treated dots as generic automations and wondered whether Wonder Full was an internal name. Current official dot messaging docs and the installed Muse model profile supplied stronger evidence; the package preserves the actual requested products.
- Its suggested event key was not adopted verbatim. The delivery guide distinguishes logical Events API event identity, transport envelopes, task identity, and outbound effects.
- A broad infrastructure matrix and every possible manifest variant would overstate tested coverage. The package is a setup skill, with live acceptance left to the configured environment.
