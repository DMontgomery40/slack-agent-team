# Team channel charter

Completed by the setup agent from authorized context; this is not a human form.

Purpose: REQUIRED
Human owners: REQUIRED
Lead (named by the user) and how to reach them: REQUIRED
Roles by strength, if assigned: OPTIONAL
Participant roster with kind (assistant or coding agent), Slack identity of each, and how to address each: REQUIRED
Verified channel members (conversations.members), including vendor apps: REQUIRED
Audience and sharing rules: REQUIRED
Thread style: top-level by default; thread exceptions and unsupported thread intake: REQUIRED
Channel vocabulary (ACK, CLAIM, READY, PASS/FAIL, HOLD, BLOCKED, DONE, HANDOFF, ETA; see the [lead guide](../references/lead.md#channel-vocabulary)) and the "heard" reaction: REQUIRED
Supported channels/DMs and peer handoffs: REQUIRED
Where results appear; working/blocked/done signals: REQUIRED
Availability and expected response behavior: REQUIRED
Notification modes, quiet hours, and mute control: REQUIRED
Task owner and completion conventions; task tracker (Jira by default for coding projects, or "none"): REQUIRED
Inspect/pause/cancel/recovery controls: REQUIRED
Shared project context or private personal memory, with current revision: REQUIRED
pstack source/revision for personal assistants, or "not used": OPTIONAL
Runtime/service owner and help route: REQUIRED

Post top-level by default ([thread policy](../references/notifications.md#thread-policy-no-threads-by-default)). Keep meaningful decisions, accountable owners, and blockers visible to the appropriate audience. Link detailed artifacts. Routine unchanged status stays quiet. A connection receipt is not task completion. Participants should be able to explain their identity, current session, available capabilities, and allowed scope from the verified roster.
